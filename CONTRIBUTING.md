# Contributing

Thanks for your interest in looot tables! We welcome bug reports, feature ideas, and feedback. **Open an issue** to tell us what you're working on or where something could be better.

You're also always welcome to fork, customize, and self-host looot tables yourself. The [README](README.md#self-host-in-5-minutes) will help you get started, and the [development guide](docs/development.md) covers local setup and working on your own version.

We don't accept external pull requests, including documentation changes. We implement accepted issues using our own development tools and AI tokens, so there's no need to prepare a patch or spend tokens before sharing an idea.

## Report a bug

Search existing issues first, then use the [bug report form](https://github.com/context-dot-dev/enrichable/issues/new?template=bug_report.yml). Include:

- What you expected and what happened.
- Minimal reproduction steps, ideally with a small synthetic CSV or example prompt.
- Whether you use enrichable.io or a self-hosted deployment; include the commit/version, browser, and Node version where relevant.
- A redacted error message or screenshot, if useful.

Never include API keys, session cookies, database URLs, MCP keys, real customer records, or unredacted network traces. Report security vulnerabilities privately using [SECURITY.md](SECURITY.md).

## Suggest a feature

Use the [feature request form](https://github.com/context-dot-dev/enrichable/issues/new?template=feature_request.yml). Describe the problem, your current workaround, and an example of the result you want. A clear problem statement helps us more than an implementation or AI-generated patch. Issues are proposals; opening one does not guarantee implementation or a timeline.

## Run your own version

Forking and modifying looot tables for your own use is welcome under the [MIT license](LICENSE). See the [development guide](docs/development.md) for local setup, architecture, migrations, and tests. You can share findings in an issue without preparing a PR.
