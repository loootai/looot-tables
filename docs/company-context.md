# Company context

Hosted sign-in schedules a brand-by-email lookup after the authorization response. A database insert claims the first attempt for the workspace (issuer + organization), so repeat authorization, reconnects, and other members do not repeat or overwrite it. The SDK does not retry this lookup. Free/disposable email, no-match, and failed results are saved; they do not trigger website research or silently retry on a query. A process interruption after claiming leaves the attempt pending rather than risking a duplicate provider call.

`researchCompany(credentials, store)` is the separate on-demand entry point. It uses the stored sign-in brand, or an explicit company domain attached to “my company” / “our company” in the query, and never resolves the email again. Explicit domains take precedence and use a separate workspace-and-domain research cache, without changing the sign-in brand. Generated column instructions retain the explicit domain for execution and reruns. `companyContextForQuery` checks user instructions for company-relative language and is used by column composition, row enrichment (including MCP), and row discovery. Row values and column-reference names cannot themselves trigger company research. Generic searches and ordinary firmographic lookups bypass company context.

Research reads the homepage and up to four relevant same-site links, summarizes offerings, buyers, use cases, documented customers, differentiators, and pricing, and persists the brief and sources for 30 days. A database lease deduplicates concurrent research across servers; expired leases allow recovery, and fencing tokens prevent late workers overwriting newer results. A failed refresh preserves the old profile but does not present it as freshly researched. No scheduled refresh or background website crawl runs at authorization. Only a subsequent relevant query refreshes an expired profile.

Company-relative language currently uses a conservative English intent matcher (`needsCompanyContext`), not an extra model call. Unknown/unsupported company contexts produce an actionable error rather than inventing a company. Self-hosted workspaces have no verified brand initialization and retain their existing prompt behavior. An existing hosted workspace initializes on its first authorization after this feature is deployed. There is no new settings UI or automatic brand retry in this change.

Apply `007_company_context.sql` and `008_explicit_company_research.sql` with the normal `npm run db:migrate` deployment step before deploying the code. No production database migration is performed by tests. Tests use PGlite and mocked provider responses.

Find rows stays open while the request runs, showing status and a Stop control. Errors (including streamed errors) appear inline, preserve the query, and allow retry. Successful completion closes the dialog. Closing a running dialog cancels its request. Column composition and save failures also appear inline.
